# Runtime dependencies. Short on purpose: every line here is something a client
# has to accept into their production environment, and something we have to
# track for advisories.
#
# Edit this file by hand, then regenerate the locks:
#
#   make lock
#
# No image installs this file. The product image installs the GENERATED
# requirements.lock.txt and the test image requirements-dev.lock.txt, both with
# every package pinned (transitive ones included) and hashed, in pip's
# hash-checking mode. A range here says what we accept; the lock says what
# ships. Before the locks a clean build resolved whatever PyPI had that day, so
# two installs of the same tag could run different code, and the test image ran
# older versions than the release image it was vouching for. `make lock` keeps
# the existing pins; `make lock ARGS="-P fastapi"` moves one package and
# `make lock ARGS=--upgrade` all of them. tests/test_requirements_lock.py fails
# while a lock disagrees with this file or with the image it runs in.
#
# Every upper bound stops at the next MINOR release of the version the test
# image runs. A range open up to the next major is a promise made on behalf of
# releases nobody has run: `sqlalchemy>=2.0,<3` let a clean install pick
# SQLAlchemy 2.1, which chose a Postgres driver the image does not ship, and the
# API did not start (BUG-114). A bound moves when `make test-all` has passed on
# the new version, in the same commit.
fastapi>=0.115,<0.142
uvicorn[standard]>=0.32,<0.53
sqlalchemy>=2.0,<2.1
alembic>=1.13,<1.20
psycopg2-binary>=2.9,<2.10
pgvector>=0.3,<0.6
pydantic>=2.9,<2.14
pydantic-settings>=2.16.2,<2.17

# Gemini. Mistral is reached over plain HTTP with the standard library, so it
